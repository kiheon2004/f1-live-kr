# 향후 게임 연결을 위한 경계 (v0.47)

이 문서는 라이브타이밍의 기존 모델링을 그대로 두고, 나중에 전략 게임이 재사용할 **상태 계산**과
**Three.js 표현**의 경계가 어디에 있는지 정리한 것이다. 이번 버전에서 게임 기능은 추가하지 않았다.
아래에 적은 함수·모듈은 모두 현재 소스에 실제로 있는 것이다(v0.47 기준, 줄 번호는 바뀔 수 있음).

공통 원칙
- 상태 계산은 순수 함수/순수 모듈(Three.js import 없음, node 테스트 가능)로 둔다. 입력은 "세션 시각 t와
  그 시각까지의 자료"이고, 같은 입력이면 같은 결과를 낸다(탐색 = 연속 재생, 라이브 = 리플레이).
- 표현(Three.js)은 상태를 받아 그리기만 한다. 화면 FPS·배속·카메라·LOD가 상태를 바꾸지 않는다.
- 게임은 "자료에서 상태를 추정하는 층"을 건너뛰고 엔진이 가진 상태를 표현층에 직접 넘긴다.
  라이브타이밍 쪽 추정 코드는 그대로 남는다.

## 1. 경기 상태 계산과 Three.js 표현 분리

| 상태(순수) | 표현(Three.js) |
|---|---|
| `smooth.js` 위치 평활(트랙 좌표 s, d) | `map3d.js` 차량 배치 |
| `aero.js` 날개 상태 `{open, front}` | `car3d.js setAero(car, open, front)` |
| `weather.js` 환경 상태(`newEnvironment`, `WeatherLog`, `evolveWet`) | `weather3d.js createWeather` |
| `pitstate.js` 피트 상태·`stopPlan` | `crew.js stopChoreo`, `map3d.js` 크루 배치 |
| `armswap.js` 팔 교차 진행 | `car3d.js placeArms`, `arms.js armSwapPose` |
| `wheelspin.js` 바퀴 회전각(이동 거리 기반) | `map3d.js` 바퀴 회전 |

새 상태 계산은 이 표의 왼쪽처럼 별도 순수 모듈에 두고, `map3d.js`에는 연결만 짧게 둔다.

## 2. 날개 상태: 게임은 엔진 값을 직접 전달

- 라이브: `map3d.js aeroPose()`가 `aero.js activeAeroAt()`(2026, **추정**) 또는 `drsAt()`(2011–2025, 측정)로
  `{open, front, why, estimated}`를 만들고, 차량 갱신에서 `c.aeroState`에 넣은 뒤 `setAero()`로 그린다.
- 경계: `c.aeroState = {open, front}` 한 곳. 게임은 `activeAeroAt`을 거치지 않고 엔진의 날개 상태
  (개방량 0..1)를 이 자리에 넣으면 된다. `activeAeroAt`의 제동·구간 진입 추정은 라이브 자료 전용이다.
- v0.47에서 `activeAeroAt`은 조회 상한(min(t+lag, now)) 이후 표본을 전혀 읽지 않는다(`passBrakes`, HOLD 1 s).

## 3. 라이브 위치 오차 보정과 게임 주행 계산 분리

- `smooth.js`는 F1 자료의 위치 오차(4 Hz, 1–2 m)를 줄이기 위한 것이다: s는 텔레메트리 속도 적분 + 위치 보정,
  d는 중앙값·가우시안. 리플레이는 양방향, 라이브는 최근 30 s를 한쪽 방향으로 다시 계산한다.
- 게임의 주행 계산(엔진이 정한 s, d, 속도)은 이미 정확한 값이므로 `smooth.js`를 거치지 않는다. 표현층이 받는
  것은 같은 형태(트랙 좌표 → 장면 좌표: `trackFrame`)로 두면 된다.
- 바퀴 회전(`wheelspin.js`)과 팔 교차처럼 "이동 거리·조향 이력"으로 정해지는 표현은 게임에서도 같은 입력
  (s, 조향각의 시간 이력)만 주면 그대로 쓸 수 있다.

## 4. 날씨 상태와 날씨 표현 분리

- 상태: `weather.js`(순수). 비 여부(측정), 노면 젖음(추정 `evolveWet`), 구름(Open-Meteo 또는 중립값),
  부분 업데이트 병합과 라이브 기록(`WeatherLog`), 구름 검증·세대 관리는 v0.45 그대로 유지한다.
- 표현: `weather3d.js`(하늘, 비 입자, 젖은 노면 재질).
- 게임은 자기 날씨 상태를 `weather.js` 환경 상태와 같은 형태로 넘긴다.

## 5. 피트 작업 시간과 애니메이션 분리

- 시간: `pitstate.js stopPlan()` – 자료(정지 시각, 새 타이어 기록, 정지 시간, 페널티)와 정책("record" 등)으로
  작업 계획을 정한다. `crew.js stopClock()`은 계획과 정지 후 경과 시간 s만으로 각 단계를 정한다.
- 애니메이션: `crew.js stopChoreo()`와 `map3d.js`의 크루 배치.
- 게임은 엔진이 정한 작업 시간(계획)을 `stopClock`/`stopChoreo`에 그대로 넘긴다. 피트 작업 시간이
  애니메이션에서 역산되지 않는다.

## 6. 시간 의존 표현의 복원 가능한 상태

- 원칙: 화면에 보이는 모든 시간 의존 표현은 "세션 시각 t + 그 시각까지의 입력 이력"의 함수여야 하며,
  프레임 사이에 남는 내부 상태는 캐시일 뿐이다. 캐시를 버리고 같은 t를 다시 계산해도 같은 결과여야 한다
  (탐색, 저장 후 복원, 게임의 되감기).
- 이미 이렇게 된 것: 날개(`activeAeroAt`), 바퀴(`wheelspin.js` – 이동 거리 기반), 피트 크루(`stopClock` –
  정지 후 경과 시간), 날씨(`weather.js` – 세션 시각).
- 팔 교차(`armswap.js`): v0.46까지는 프레임마다 이어지는 상태(q)여서 탐색·FPS에 따라 달랐다. v0.47의 수정과
  복원 가능한 상태의 정의는 아래 "팔" 항목과 보고서(arms)를 본다.
