# 검증 자료

README의 검증 수치가 무엇을, 어떤 조건에서 잰 것인지 정리한 문서입니다. 모든 수치는 2026-11-01 작업 중 기록한 값입니다. 따로 적은 자동 테스트를 빼면, 이 문서를 쓰면서 다시 측정하지는 않았습니다.

## 측정 도구

모두 앱 안의 개발용 함수이며, 실제 화면과 같은 그리기 경로(`map3d.js`의 `updateCars`)를 거친 **최종 위치와 자세**를 잽니다.

| 도구 | 위치 | 재는 것 |
|---|---|---|
| `Map3D.poseScan(t0, t1, { fps })` | `src/renderer/map3d.js` | 보이는 모든 차의 최종 자세를 정해진 fps로 기록하고 이상 종류별로 셉니다. **jump**: 한 프레임 이동이 (속도 × 1.25 + 8 m/s) × 프레임 간격보다 큼. 그 밖에 yaw(방향 급변), lift(높이 급변), height(노면과 0.6 m 넘게 차이) |
| `Map3D.recordLive(secs)` | `src/renderer/map3d.js` | 실제 재생 중 몇 초 동안의 카메라·차 상태. v0.54부터 `sinkCm`(그린 차가 도로 아래로 내려간 깊이) 포함 |
| `Map3D.pitPathScan`, `Map3D.game.pitTrace` | `src/renderer/map3d.js`, `src/renderer/pitcheck.js` | 피트 레인에서 그린 차의 좌우 이동, 방향 변화, 정비 전후 작업 구역 주행 거리 |
| `Map3D.overlapScan` | `src/renderer/map3d.js` | 차량 모양 상자(5.6 × 2.0 m)끼리 겹친 차량 쌍-프레임 |

이 함수들을 여러 경기에 돌린 실행 스크립트, 원시 로그, 작업 보고서는 크기가 크고 개인 PC 경로가 들어 있어 저장소에 넣지 않았습니다. 아래 "근거"에는 그 기록의 이름만 적었습니다.

## 수치별 근거

### 1. 2026 헝가리 결승, 설명할 수 없는 이동 29,835 → 146

- **대상:** 2026 헝가리 그랑프리 결승, 출발 10분 전부터 세션 끝까지, 화면에 보이는 모든 차.
- **단위:** 차량-프레임(한 프레임에서 한 차가 jump 조건에 걸리면 1). 두 실행 모두 67,796 프레임, 10 fps.
- **비교:** 같은 경기·같은 구간·같은 도구. 전 = v0.52.0 + 측정 함수만 더한 코드(`0b3d821`), 후 = v0.53 개발 브랜치(2026-11-01 12:34 기록, 최종 v0.53.0 출시 전 코드).
- **같이 기록된 값:** yaw 53,630 → 402, lift 9,222 → 15, height 5,785 → 161.
- **관련 커밋:** [`40bda05`](https://github.com/kiheon2004/f1-live-kr/commit/40bda05), [`884a1b6`](https://github.com/kiheon2004/f1-live-kr/commit/884a1b6).
- **근거:** 작업 로그 `scan_hun2026_before.log`, `scan_hun2026_m.log`, v0.53 완료 보고서 §2.
- **주의:** 이 수치는 v0.53에서 잰 것이며 v0.54에서 다시 재지 않았습니다. 같은 경기를 에피소드(같은 차·같은 종류가 1초 안에 이어지면 1건) 단위로 센 47경기 스캔에서는 v0.52 2,516건 → v0.53 73건입니다(측정 구간: 출발 5분 전부터).

### 2. 47경기 스캔

- **대상:** 캐시에 있던 결승·스프린트 47개(2024 영국 + 2025 + 2026 시즌).
- **결과:** v0.53 코드(`8a727eb`)로 47경기 모두 오류 없이 스캔 완료. 출발 5분 전부터 세션 끝까지, 10 fps, `poseScan`.
- **비교:** v0.52 코드와의 비교는 이 중 13경기만 했습니다. 47경기 전체의 전후 비교가 아닙니다.
- **근거:** v0.53 전체 스캔 보고서(`sweep.md`), 로그 `after_all.log`.
- **이 스캔에서 찾은 문제:** 출발 전 차가 40–200 m 순간 이동하는 새 문제가 47경기 중 35경기에서 나왔습니다. 이후 [`341ca63`](https://github.com/kiheon2004/f1-live-kr/commit/341ca63)(`startplan.js`)에서 6경기 기준 58 → 16건으로 줄였고, 남은 16건은 자료 자체가 멈췄다 도약하는 경우입니다.

### 3. 온보드 차체 가라앉음 최대 5.1–10.1 m → 2.7 cm 이하

- **대상:** 온보드·1인칭 시점에서 카메라가 타고 있는 차. 노리스(NOR) 차, 2025 헝가리·2025 모나코 다시보기, 2025 헝가리 맥라렌 게임.
- **단위·통계:** `recordLive` 10초 기록의 `sinkCm`, cm, p50 / p95 / 최대.
- **결과(10배속 최대값):** 헝가리 온보드 515 → 2.7, 헝가리 1인칭 513–534 → 2.1, 모나코 온보드 982–1,006 → 2.7, 모나코 1인칭 981–1,010 → 2.6, 게임 온보드 558–564 → 1.8 cm. 1배속에서는 최대 12.5 → 2 cm(헝가리 온보드).
- **비교:** 같은 장면을 수정 전 코드와 수정 후 코드에서 각각 실행했습니다(같은 실행이 아닙니다).
- **관련 커밋:** [`650b594`](https://github.com/kiheon2004/f1-live-kr/commit/650b594) (`src/renderer/ride.js`), 테스트 `test/ride54.test.js`.
- **원인:** 차의 높이·경사를 실제 시간 기준으로 천천히 따라가게 해 두어서, 오르막에서 차가 도로보다 늦게 올라갔습니다. 배속이 높을수록 커졌습니다.
- **화면 확인:** 10배속 수정 전 화면에서는 카메라가 땅 밑에 있었고, 수정 후에는 정상 시야인 것을 스크린샷으로 확인했습니다.
